Summary of changes in STIR release 6.5

Overall summary

This version is 100% backwards compatible with STIR 6.4, aside from bug fixes of course. In particular, the "bucket" information for the Siemens mMR has changed (see below).

This is a release with several major updates, including dead-time correction for the Siemens mMR, TOF support with "block" and "generic" scanners, initial support for PETSIRD 0.12, GATE-ROOT support for "block" scanners and support for SimSET block detectors. More detail is below.

Main code contributions were by Nikos Efthimiou (UMCG), Alan Osys (LSBU), Daniel Deidda (NPL), Kris Thielemans (UCL).
Overall overview and release management was by Kris Thielemans (UCL).

Summary for end users (also to be read by developers)

Bug fixes

  • Fix incompatibility problem with ROOT 6.38 or later. Previous versions of STIR either crashed or threw an error Entry is null.
    PR #1741.
  • Fix GE Signa PET/MR (and other RDF9 scanners?) header reading problem. Previous version of STIR got caught on the \0's present in the header and threw an error and stopped.
    PR #1777.
  • Fix ProjMatrixByBinSPECTUB and ProjMatrixByBinPinholeSPECTUB returning an empty LOR for the first bin that is requested in each view (when not all views are kept in the cache). This made forward and back projection inconsistent when they are used one after the other on the same view, as in the gradient of the Poisson log-likelihood.
    See issue #1576.

New functionality

General

  • Initial support for reading PETSIRD 0.12 list-mode data, the proposed standard for PET list-mode data from the Emission Tomography Standardization Initiative (ETSI). Some limitations include single layer, single module type geometry. Dead-time correction for PETSIRD data uses the alive-time fractions per crystal that are stored in the PETSIRD file. Module-pair alive-time fractions are not supported yet.
    See also STIR2PETSIRD for using STIR to write PETSIRD data.
    PR #1604, PR #1770.
  • Initial support for even number of TOF bins.
    PR #1604, but see Issue #1751.
  • enable TOF for BlocksOnCylindrical/Generic
    PR #1746.
  • Enable GATE ROOT support BlocksOnCylindrical. This requires extra keywords in the headers for the ROOT file (.hroot). The keywords are the same as in the Interfile header. For example 
             Scanner geometry (BlocksOnCylindrical/Cylindrical/Generic)  := BlocksOnCylindrical
         Distance between crystals in axial direction (cm)           := 0.63
         Distance between crystals in transaxial direction (cm)      := 0.42
         Distance between blocks in axial direction (cm)             := 3.78
         Distance between blocks in transaxial direction (cm)        := 3.78
    This change makes STIR geometry much closer to GATE ROOT, which for instance allowed us to decrease the tolerances in our tests.
    Warning: This is currently only supported for 
            GATE scanner type := GATE_Cylindrical_PET

    Note that the user of "virtual" crystals and block geometry likely will lead to wrong results (and is untested).
    PR #1746.
  • New utility conv_SimSET_crystal_pairs_to_STIR and script conv_SimSET_crystal_pairs_to_STIR.sh to convert SimSET block-detector output binned by crystal pair into STIR projection data, for Cylindrical and BlocksOnCylindrical scanners.
    PR #1774.
  • Dead-time correction for Siemens mMR (ECAT8) data. lm_to_projdata now writes the singles rates of each time frame to a JSON file (<output prefix>_f<frame>_singles.json), which can be given to BinNormalisationFromECAT8 with the keywords use_dead_time and singles filename. See the User's Guide.
    PR #1770.

Changed functionality

  • The singles-unit layout of the Siemens mMR in Scanner was corrected: a bucket is now 1 axial x 2 transaxial blocks (a singles unit of 8 x 18 crystals), i.e. 8 x 28 singles units, instead of 2 x 1 blocks (16 x 9 crystals), i.e. 4 x 56. This changes the mapping from a detector to its singles unit (e.g. Scanner::get_singles_bin_index()), and therefore the singles-based dead-time correction and any singles rates that are looked up per bucket for this scanner.
    WARNING: This means that the information on the Interfile header for the projection has now changed to 
          Number of blocks per bucket in transaxial direction         := 2; was 1
      Number of blocks per bucket in axial direction              := 1; was 2
      Number of crystals per singles unit in axial direction      := 8; was 16
      Number of crystals per singles unit in transaxial direction := 18; was 9
    The Siemens-mMR examples have been updated accordingly.
    PR #1770.
  • Add extra run-time checks for BlocksOnCylindrical scanners. This includes basic checks on crystal/blocks spacing when constructing the geometry (calling error() when they fail) and a check on ring-distance (calling warning() when it fails), see Issue 1753.
    The checks are performed when calling Scanner::set_up(), which for instance is called after parsing headers.
    To enable testing, we have now added approximate block-info for the GE Signa PET/MR. However, it still defaults to using Cylindrical geometry.
    PR #1746.

Build system

  • CMake: fix problem compiling STIR registries where fmt.h is not found.
    PR #1604.
  • SWIG: update SWIG files for compatibility with SWIG 4.5
    PR #1743.

Known problems

See our issue tracker.

What is new for developers (aside from what should be obvious from the above):

Changed functionality

  • Allow local running of a GitHub Action via act (see local-CI.md.
    PR #1604.
  • Made (deprecated) ProjDataInfoCylindricalNoArcCorr::find_cartesian_coordinates_given_scanner_coordinates protected to avoid usage as much as possible.
    PR #1746.

New Deprecations and renames

  • Scanner::get_detector_map_sptr() is now deprecated. Use get_detector_coordinate_map() instead (or get_detector_coordinate_map_sptr if you need to).
    PR #1731.
  • Scanner::set_up() now always needs to be called explicitly after construction of a scanner. This will be enforced in v7.0.

Code improvements

  • Added class ProjDataInfoPETScannerWithDiscreteDetectors. This class should/can be used for accessing members such as get_det_pos_pair_for_bin etc., i.e. any members that assume that there is a correspondence between detection positions and bins.
    While it's currently an alias for ProjDataInfoCylindricalNoArcCorr, this is expected to change.
    PR #1746.

Test changes

All new features and most code changes were accompanied by new tests.

  • ProjDataInfo*::get_m() etc now have explicit consistency checks.
    PR #1731.
